# AMBA APB Protocol Verification Using SystemVerilog

## Project Overview

This project focuses on the functional verification of an AMBA APB (Advanced Peripheral Bus) Master using SystemVerilog. The verification environment was developed using object-oriented verification concepts such as Transaction, Generator, Driver, Monitor, Scoreboard, Environment, and Test classes.

The APB Master design was verified using randomized read and write transactions generated by the testbench. Waveform analysis was performed using EPWave in EDA Playground.

## AMBA APB Protocol

The Advanced Peripheral Bus (APB) is a low-power and low-complexity bus used to connect peripheral devices.

### APB Transfer Phases

#### 1. Setup Phase

During this phase:

* PSEL = 1
* PENABLE = 0
* Address and control information become valid

#### 2. Access Phase

During this phase:

* PSEL = 1
* PENABLE = 1
* Data transfer takes place

A transfer completes when:

* PREADY = 1

---

## APB Master FSM

The APB Master is implemented using a finite state machine containing three states.

| State  | Description                     |
| ------ | ------------------------------- |
| IDLE   | Waiting for transaction request |
| SETUP  | Address and control phase       |
| ACCESS | Data transfer phase             |

### State Transition

```text
IDLE → SETUP → ACCESS → IDLE
```

The waveform confirms successful state transitions throughout the simulation.

## Verification Environment Architecture

The verification environment consists of the following components:

### Transaction

Stores transaction information such as:

* Read/Write control
* Address
* Data

### Generator

Generates randomized APB transactions and sends them to the driver through a mailbox.

### Driver

Receives transactions from the generator and drives them onto the APB interface.

### Monitor

Observes APB bus activity and captures completed transactions.

### Scoreboard

Compares monitored values against expected values and reports PASS or FAIL.

### Environment

Connects all verification components together.

### Test

Creates and runs the verification environment.

## Signals Verified

### Input Signals

| Signal  | Description        |
| ------- | ------------------ |
| PCLK    | APB Clock          |
| PRESETn | Active-Low Reset   |
| start   | Transaction Start  |
| rw      | Read/Write Control |
| addr    | Address Input      |
| wdata   | Write Data         |

### Output Signals

| Signal  | Description          |
| ------- | -------------------- |
| PSEL    | Peripheral Select    |
| PENABLE | Enable Signal        |
| PWRITE  | Write Control        |
| PADDR   | APB Address          |
| PWDATA  | APB Write Data       |
| PRDATA  | APB Read Data        |
| done    | Transaction Complete |

## Verification Checks Performed

### Check 1: APB Setup Phase

Verified:

```text
PSEL = 1
PENABLE = 0
```

during the setup phase.

### Check 2: APB Access Phase

Verified:

```text
PSEL = 1
PENABLE = 1
```

during the access phase.

### Check 3: PWRITE Verification

Verified:

```text
PWRITE == rw
```

for every transaction.

### Check 4: Address Verification

Verified:

```text
PADDR == addr
```

for all transactions.

### Check 5: Write Data Verification

Verified:

```text
PWDATA == data
```

during write transactions.

### Check 6: Read Data Verification

Verified correct read data generation during read operations.

### Check 7: Transaction Completion

Verified correct assertion of:

```text
done = 1
```

after successful transfer completion.
