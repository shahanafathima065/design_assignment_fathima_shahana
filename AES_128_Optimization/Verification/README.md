# AES-128 Encryption Core Verification

## Overview

This repository contains the design and verification of an AES-128 Encryption Core.

The project verifies the correctness of AES encryption using a complete SystemVerilog verification environment developed in Vivado Simulator (XSIM).

The verification environment automatically applies AES test vectors, captures DUT outputs, compares expected and actual ciphertext values, performs assertion checking, collects functional coverage, and generates code coverage reports.

# Verification Procedure

## Step 1 – Generate Test Cases

The Generator creates AES transactions containing:

* Plaintext
* Key
* Expected Ciphertext

The project uses:

* AES Appendix-B Vector
* FIPS-197 Vector
* NIST Test Vectors
* Corner Case Test Vectors

---

## Step 2 – Drive Inputs to DUT

The Driver receives transactions from the Generator.

It applies:

* IN_valid
* IN_state
* key

to the AES DUT through the interface.

---

## Step 3 – AES Encryption

The DUT performs AES encryption internally.

The AES core processes:

* SubBytes
* ShiftRows
* MixColumns
* AddRoundKey

across multiple AES rounds.

---

## Step 4 – Monitor DUT Output

The Monitor continuously observes:

* OUT_valid
* OUT_state

When OUT_valid becomes HIGH, the Monitor captures the ciphertext generated by the DUT.

---

## Step 5 – Scoreboard Comparison

The Scoreboard receives:

Expected Ciphertext → from Generator

Actual Ciphertext → from Monitor

Both values are compared bit-by-bit.

If:

Expected = Actual

Result = PASS

Otherwise:

Result = FAIL

---

## Step 6 – Assertion Checking

Assertions continuously verify important properties:

* OUT_valid pulse width
* No X/Z values at output
* Proper reset behavior

Any violation immediately reports an assertion failure.

# Waveform Verification

The following signals are monitored:

* reset_n
* IN_valid
* IN_state
* key
* OUT_valid
* OUT_state

Verification from waveform is performed as follows:

1. Apply plaintext and key.
2. Assert IN_valid for one clock cycle.
3. Wait for AES processing latency.
4. Observe OUT_valid becoming HIGH.
5. Read ciphertext from OUT_state.
6. Compare OUT_state with the expected AES ciphertext.

Example:

Input Plaintext:

00112233445566778899AABBCCDDEEFF

Key:

000102030405060708090A0B0C0D0E0F

Expected Ciphertext:

69C4E0D86A7B0430D8CDB78070B4C55A

Waveform Observation:

OUT_state = 69C4E0D86A7B0430D8CDB78070B4C55A

Verification Result:

PASS
